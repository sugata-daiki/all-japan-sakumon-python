　この章では, 以下のことができるようになります. 
- ファイルに数値や文字列を書き込み, 保存する ("ファイル出力").

## ファイル出力
"simpleOutput.py"を参照してください. 
### 内容の説明
```python
fibonacci_seq = [1, 1]
```
配列の形で, `fibonacci_seq`を初期化します. 

#### 注意: 初期化は必ずやろう
　特にC/C++といったより低級な言語を取り扱う場合は, 初期化は必ずやりましょう. もっと言えば, クラスを設計するときには, ユーザーが特に何もしなくとも内部的に勝手に初期化されるようにするとともに, ユーザーによって無効な値が渡されたときには例外を投げるようにしておきましょう. これだけのことで, 無駄なデバッグの手間を省くことができます. 

```python
[fibonacci_seq.append(fibonacci_seq[-1] + fibonacchi_seq[-2]) for _ in range(8)]
```
さっき作った配列`fibonacci_seq`の配列の末尾2つを取り出して, それらを足し合わせた結果をまた配列の末尾に追加する, ということを8回やっています. 

#### 注意: 基本的に変数の再代入はやめよう& アルゴリズムは関数化しよう
上のコードは正しいコードですが, 可読性に乏しく, バグを埋め込む可能性があります. 例えば, `fibonacci_seq`を`fibonacchi_seq`から作成・更新していますが, このように変数を変更してしまうとプログラムが長くなったときに変数がどう変更されたのかが分かりにくくなってしまいます. 特にpythonは動的型付け言語であり, 変数がいかなる型であっても後で変更してしまえるがゆえに, 後から型がどのように変更されていったか追跡するのは困難です. もう1つ, `fibonacchi_seq`を構成する方法は`a_n = a_n-1 + a_n-2`というアルゴリズムです. こういうアルゴリズムはべた書きせず, `add_fibonacchi_seq(arr)`のように適切な名前を付けた上で関数化すると, 後から読み返すときに非常に非常に非常に楽です. こういうと関数呼び出しのボトルネックを気にする人がいるのですが, そこまでの最適化をしないといけないケースは本当に稀です. 普通はもっと別のところにボトルネックがあるものですし, 何より早計な最適化はしない方が吉です. 

```python
output_arr = np.array([[i+1, fibonacchi_seq[i]] for i in range(10)], dtype = int)
```
`fibonacchi_seq`を, その通し番号 ((1, 1, 2, 3, ...) なら先頭の1に1, 次の1に2, 2に3, 3に4, ...といった感じです) とともに先頭から並べた配列を作成しています. `fibonacchi_seq`の配列の長さが10なので10回for文を回しています. 

```python
np.savetxt("test.txt", output_arr, fmt='%s')
```
`output_arr`を文字列の形 (`fmt='%s'`) で保存します. 

## パスの操作
Input_with_pathlib.pyを参照してください. 
### 内容の説明
```python
def make_filePath(file_name: str) -> str:
    """Make file path.

    Args:
        file_name (str): name of input file

    Returns:
        str: path to input file

    """
    exe_dir = Path(__file__).parent
    file_path = exe_dir / file_name

    if file_path.exists():
        return file_path
    else:
        raise FileNotFoundError(f"File not found: {file_path}")
```
ファイルパス (コンピュータにおけるファイルの位置を指し示すものです) を作成する関数です. このように, 複雑な処理は関数の単位で切り分けておくと, コードがすっきりして可読性が増します. 

`(file_name: str) -> str:`はモダンなpythonの関数における型チェックの方法で, 関数の入力が文字列型, 出力が文字列型であるという制約を課しています. なぜこのような制約が必要なんだ?と思うかもしれませんが, 例えば「整数に+1する」処理はありえますが, 「文字列に+1する」処理はまああり得ないですよね. このように, プログラマにとって想定外の操作をユーザーがしてしまうことを防ぐためにも, このような制約が必要になってきます. 

`if file_path.exists()...`の部分では, 作成したファイルパスにファイルが存在しているかを確認し, なければ例外を投げる処理を行っています. こういう例外処理を1つ1つ書いていくことが, プログラムを書く上で大事になってきます.
